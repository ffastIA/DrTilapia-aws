## 4. Preservar o piso de recusa em cosseno puro

- [x] 4.1 Garantir que `_select_context_docs` (de `restore-rag-answer-quality`) recebe e usa o score de **cosseno bruto**, não o score RRF fundido, para a decisão de recusa (`< REFUSAL_FLOOR_SIMILARITY`). Implementado: `top = max(similaridade de docs SEM "lexical_rank" na metadata)`, nunca `ranked[0]`.
- [x] 4.2 Garantir que `CONTEXT_ABSOLUTE_FLOOR` (de `restore-rag-answer-quality`) só se aplica a documentos que entraram pela via vetorial — um documento que só apareceu pela via léxica é avaliado pelo próprio `lexical_rank`, não pelo piso de cosseno (que ele não tem). Docs com `lexical_rank` na metadata sempre passam o filtro da janela relativa.
- [x] 4.3 Teste unitário dedicado: fusão RRF que promove um documento de baixa similaridade de cosseno para o topo do ranking fundido não afeta a decisão de recusa, que continua baseada só no cosseno do melhor candidato. `tests/test_hybrid_search.py::TestRefusalFloorIgnoresFusedRank` (4 testes): doc léxico-only no topo do ranking fundido não bypassa recusa quando o melhor cosseno real está abaixo do piso; não recusa quando o melhor cosseno real está acima (mesmo não sendo o topo do ranking fundido); `CONTEXT_ABSOLUTE_FLOOR` não exclui docs léxico-only; comportamento idêntico ao pré-change quando não há docs léxico-only presentes (híbrida desligada). Verificado também ao vivo: pergunta claramente fora do escopo ("receita de bolo de chocolate") com `top_similarity_raw=0.221` recusou corretamente mesmo com busca híbrida ativa.

## 5. Sinal léxico complementar ao gate de recusa

- [x] 5.1 Implementar contagem de termos discriminativos: um termo da pergunta conta só se aparece em ≤ 20% dos chunks do corpus (usando a frequência de documento da task 2.5). `_has_discriminative_lexical_match` — considera "match" só quando `0 < freq <= LEXICAL_DISCRIMINATIVE_MAX_DOC_FREQ` (frequência 0 não conta: um termo ausente não "casa" com nada, mesmo sendo tecnicamente ≤20%).
- [x] 5.2 Quando a similaridade do melhor candidato está na zona intermediária (entre `REFUSAL_FLOOR_SIMILARITY` e `PRIMARY_RPC_SIMILARITY_THRESHOLD`) e nenhum termo discriminativo casa lexicalmente, tratar como sinal adicional favorecendo recusa. Implementado em `_retrieve_docs_via_rpc`, estritamente depois da decisão de cosseno — nunca resgata uma recusa por cosseno, nunca enfraquece uma confiança já alta.
- [x] 5.3 Testar contra o conjunto adversarial de `fix-rag-eval-harness-fidelity` — em particular confirmar e documentar que `oos-fis-carpa`/`oos-rpl-streptococcus` (vocabulário técnico compartilhado, entidade errada) permanecem difíceis mesmo com o sinal léxico, já que esses termos SÃO discriminativos e SÃO encontrados — esse é o caso que só `grade_context` (semântico, de `add-rag-self-correction-loop`) resolve. **Confirmado ao vivo** (`HYBRID_SEARCH_ENABLED=true`): `oos-fis-carpa` (top_sim=0.619, zona intermediária) e `oos-rpl-streptococcus` (top_sim=0.622, zona intermediária) — ambos com `_has_discriminative_lexical_match=True` (termos "fis"/"rpl"/"carpa"/"streptococcus" genuinamente presentes no corpus, só a espécie/patógeno está errada), `selection_reason='relative_window'` — nenhum dos dois foi recusado pelo sinal léxico, exatamente como o design previu.

Testes: `tests/test_hybrid_search.py`, classes `TestDiscriminativeLexicalCoverage` (5 testes) e `TestIntermediateZoneLexicalSignalWiring` (4 testes) — cobrem termo discriminativo presente/ausente, só termos genéricos, falha de infraestrutura não bloqueia sozinha, sinal ignorado fora da zona intermediária ou com busca híbrida desligada.

**Nota de segurança encontrada durante a verificação deste grupo:** `tests/test_backend_api.py::test_cleanup_vector_base_success` mockava o método errado (`cleanup_vector_base` em vez de `cleanup`, o que o endpoint `/admin/vector-base/cleanup` realmente chama) — o mock nunca interceptava a chamada real, então toda execução da suíte completa (`pytest tests/`) disparava uma limpeza real da base vetorial de produção. Corrigido; ver memória do projeto para o histórico completo (7 incidentes de base vazia ao longo desta sessão, todos causados por isso).
